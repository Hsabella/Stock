# 止损线锚点修正设计（持仓健康度 ↔ 抄底灯规则对齐）

日期：2026-07-28 ｜ 状态：**已实施**（v2，评审修订后落地；修订记录见 §7）
涉及代码：`quant/live/portfolio.py` · `quant/live/daily_brief.py` · `watchlist.yaml`
上游回测：[docs/quant/stock_lights_report.md](../../quant/stock_lights_report.md)

## 1. 问题

晨报【持仓健康度】的「止损线」与抄底灯回测定案的止损规则**锚点不同**，导致
**任何从高位腰斩处买入的仓位，在买入第一天就被判「已破❗」**。

两处规则并列：

|            | 实盘（`portfolio.py:133-`）               | 回测定案（`stock_lights.py:243-250`）                      |
| ---------- | ------------------------------------------- | ------------------------------------------------------------ |
| 初始止损   | `entry × (1 - 0.08)`                     | 左侧臂`entry - 3.0×ATR14(信号日)`右侧臂 `entry × 0.92` |
| 追踪线     | `近20日最高收盘 - 2×ATR14`               | `入场以来最高收盘 - 2×ATR14`                              |
| 合成       | `max(hard, trail)` 取严者，**静态** | `stop = max(stop, line)` **棘轮，只升不降**          |
| 追踪线锚点 | 可能落在**入场之前**                  | 恒在**入场之后**                                       |

`stock_lights.py:66` 的注释已记录该差异（「与实盘 atr_2 同参、**锚不同**」），
即差异是刻意保留的；但「新建仓的坑底票天生已破」这一后果未被推演，晨报也未标注。

## 2. 证据：Chandelier 不是坏，是用错了地方

`近20日最高收盘 - k×ATR` 是标准 Chandelier 趋势跟踪出场。账户里两笔实盘正好
把它的适用边界划出来：

| 仓位             | 成本                 | 20日高锚点来源                                                  | 晨报读数                                                   | 结果                                |
| ---------------- | -------------------- | --------------------------------------------------------------- | ---------------------------------------------------------- | ----------------------------------- |
| 科创50ETF 588000 | 1.835                | 入场后最高收盘 2.344（06-30，qfq 现基准；初稿写 2.02 系盘中价） | 07-22 止损线 2.05 已破                                     | 卖 1.968，**+7.2%，正确锁利** |
| 东材科技 601208  | 41.465（07-23 买入） | 20日高 ~70，是**入场前**的                                | 07-27 止损线 60.92 已破（回放核实=60.916，07-24 收盘口径） | 买入首日即"已破"，07-27 清仓 41.88  |

- 东材止损线比成本高 **47%**，该仓位存续期内不可能不破。
- 07-28 东材现价 43.32，比卖出价高 3.4%。
- 区分变量只有一个：**锚点是在入场前还是入场后设的。**

这与抄底灯直接冲突：抄底灯 setup 是「距 120 日高 ≤ -35%」，
即**它推荐买入的每一只票，持仓健康度都会当天判其止损**。

## 3. 已否决的方案

### 3.1 `max(入场价, 入场以来最高收盘) - k×ATR`（初版提案，否决）

1. **不可实现**：`watchlist.yaml` 的 HELD 条目只有 `entry_price`，**没有 `entry_date`**
   （有 `exit_date`/`exit_price`，入场侧缺失），"入场以来"窗口起点不存在。
2. **参数错向危险侧**：实盘 `atr_k=2.0`，该式给初始止损用 2×ATR，而回测定案左侧臂是
   3×ATR。`stock_lights.py:64` 明确警告「约 2 个 ATR 的 8% 对小票是打脸机器」——
   比现状更容易被打出来。
3. **丢失棘轮**：回测棘轮的是 **stop 本身**而非锚价。ATR 会变大，
   `最高收盘 - 2×ATR` 并不单调，无棘轮会出现止损线下移。
4. 未论证"统一"的正当性：3×ATR 只在抄底灯左侧臂（距高≤-35%）上验证过。

### 3.2 浮盈门控：仅当现价 > 成本时启用 Chandelier（否决）

免 schema 改动，但**对目标场景无效**：东材 07-27 为 +0.6% 浮盈，仍会取用
60.92 的错误锚点。不解决问题。

### 3.3 最小改动：`line = hard`，Chandelier 降级为纯展示（否决）

零 schema 改动，立刻消除矛盾，且与 `trail_line()` 在【回补观察】（"站回趋势线"，
`daily_brief.py:245`）和【ETF观察】（"ATR趋势线"，`daily_brief.py:271-274`）中的
既有命名一致——同一函数本就在这两处被当作趋势读数使用。

**否决理由**：牺牲赢家的锁利棘轮。科创50ETF 那笔 +7.2% 不会触发，
8% 硬止损在 1.688，将从 2.02 一路持有回 1.91（07-28 实际价）。代价实测可见。

## 4. 定案设计

### 4.1 数据：新增 `entry_date`

`watchlist.yaml` HELD 条目增加 `entry_date`，与既有 `exit_date` 对称：

```yaml
- { symbol: "002506", name: "协鑫集成", state: "HELD", position: 20000,
    entry_price: 2.49, entry_date: "2026-07-28", entry_arm: "left" }
```

- `entry_arm`: `left`（抄底灯建仓）/ `right`（回补接回或其他右侧入场），默认 `right`。
- 加仓过的仓位取**首次建仓日**（棘轮窗口覆盖完整持有期）。
- 附带收益：解锁回测里 `MAX_HOLD = 60`（60 交易日强制评估），当前实盘无法实现。

### 4.2 三条线，按入场臂选初始止损

```python
硬止损   = entry × (1 - hard_stop_pct)            # 0.08 → ×0.92，= 回测右侧臂 RIGHT_STOP
初始ATR  = entry - 3.0 × ATR14(信号日)            # = 回测左侧臂 LEFT_STOP_ATR，仅 entry_arm=left
                                                  #   信号日=入场前一交易日（回测用 atr[t] 而非入场当日）
棘轮     = max_u( 入场至 u 日最高收盘 - 2.0 × ATR14(u) )   # u 遍历入场后每个交易日
stop     = max(该仓位适用的初始止损, 棘轮)                  # 只升不降
```

**棘轮从当前 K 线整段确定性重算，不持久化**（v2 修订）：对入场以来每一天算
`cummax(close) − k×ATR(u)` 再取历史最大——与回测持仓循环
（`stop = max(stop, hi − k×atr)`）逐日等价。初稿的 `stop_ratchet.csv` 方案被否决：
K 线是 qfq 前复权，每个除权日全部历史价重排，存盘的 stop 价位会跨复权基准失效
（除权次日必假破线/假安全）；重算天然免疫，且回滚无状态残留。
降级路径：`entry_date` 缺失 / K 线起点晚于入场日 / 入场后窗口 ATR 有缺 /
左臂信号日 ATR 不可算 → 一律退回仅硬止损并标 ⚠️ degraded，禁止静默用残缺窗口。

入场臂到规则的映射恰好落在回测的两条臂上：

- **抄底灯建仓** = 左侧买弱势 → `entry - 3×ATR` 初始
- **回补接回** = 三条件含「站回趋势线」，**按定义即右侧入场** → `entry × 0.92` 初始
- 两者均叠加 since-entry 的 2×ATR 棘轮

### 4.3 东材科技验算（已实测，真实 K 线回放）

- 硬止损 = 41.465 × 0.92 = **38.15**
- 棘轮实测 = **33.63**（07-27；初稿估算 36.7 因 ATR 低估——实际 ATR14≈4.8 而非 2.5）
  → 低于硬止损，不生效
- stop = **38.15**，逐日距离 +8.7%（07-23）/ +9.4%（07-24）/ +13.6%（07-27），**全程不破**
- 同期旧口径逐日 63.23 / 60.92 / 61.10，**全程已破**——bug 与修复各自被回放精确复现
  （旧口径 07-24 读数 60.916 与晨报实盘 60.92 对上，回放口径可信）

该仓位不会被赶出，07-28 现价 43.32。
588000 回放同样通过：新棘轮随 6 月涨势抬至 **2.153**（06-30 峰值日）后保持，07-02 起
稳定判破（比实际 07-22 卖出早 14 个交易日、卖点高约 7%）；旧口径同期在
2.153→2.047 间**回落**且 07-07~07-14 一度"解破"再"复破"——非单调线做卖出驱动的
决策噪声被回放坐实，棘轮消除之。完整逐日对照见实施计划附录。

### 4.4 展示层：拆分「止损线」与「趋势线」两个概念

`daily_brief.py:184-185` 当前把合成后的 `stop_line` 印为「止损线」。修正后：

- **止损线** = §4.2 的 `stop`，唯一驱动卖出判断
- **ATR趋势线** = `trail_line()` 原义（近20日最高收盘 − k×ATR），仅作趋势读数，
  与【回补观察】【ETF观察】的既有用法统一命名

## 5. 未验证部分与风险（v2 修订）

1. **右侧臂 + since-entry 棘轮的"组合"本就是回测跑法**——初稿称"未单独跑过"不准确：
   `stock_lights.py` 的 R 风格事件回测中右臂交易同样走棘轮循环。真正未验证的是把该
   规则配给**"回补接回"这一入场分布**（回测不模拟回补场景），重跑 `stock_lights`
   覆盖不到它——那只是回归检查（确认左臂既有结论未被改崩），不是对新映射的验证。
   新映射的证据只能靠实盘攒：晨报读数落 log，攒够样本再评估。
2. **K 线覆盖不足的降级已实现**：entry_date 缺失 / K 线起点晚于入场日 / 窗口内 ATR
   有缺 / 左臂信号日 ATR 不可算，四条路径均退回仅硬止损并标 ⚠️（有测试锁住）。
3. **`entry_arm` 依赖人工标注**，标错会把左侧仓位配上 8% 硬止损（过紧）。
   已加廉价体检：left 仓位检查入场时距 120 日高是否 ≤ −25%（抄底灯 setup 最浅档），
   不满足在晨报标"⚠️左臂标注存疑"。
4. 本次修改影响卖出决策，属高风险变更。初稿的"并行观察数日"不可行——当前 0 只
   HELD（07-27 清仓后），无观察对象；已改为**真实 K 线历史回放**验收（东材 +
   588000 两笔，见 §4.3），实时观察顺延到下一笔新仓自然发生。
5. **遗留（前置已存在，非本次引入）**：`entry_price` 是名义成交价，K 线是 qfq 基准；
   持有期内若遇分红除权，硬止损/左臂初始线（entry 锚定）与 K 线收盘价会差一个复权
   因子。棘轮不受影响（全部从当前基准 K 线重算）。卫星仓持有期短（≤60 交易日强制
   评估），撞上除权概率低，暂不处理；处理需引入除权因子数据源，另行立项。

## 6. 影响面 / 不改的部分

- **核心宽基 ETF（`account.etf`，如 159919）维持现状：不设个仓止损线。**
  它是 40-50% 战略配置，风险由红绿灯敞口规则（🟢100% / 🔴70%）管理，
  再叠个仓止损会与配置目标互相打架。当前已是该行为，保持。
- `trail_line()` 在【回补观察】`daily_brief.py:245` 与【ETF观察】`:271-274` 的
  语义不变（趋势读数），仅【持仓健康度】的用法改变。
- 相关联但独立的问题：【回补观察】条件①对 588000 用「科创50 在 MA200 之上」判定，
  当前 🟢 系 MA200 慢均线滞后所致（科创50 已破 MA20/MA50，距 60 日高 -18.1%），
  建议另行改为「站回 MA50」。**不在本次范围内**，单独记录。
